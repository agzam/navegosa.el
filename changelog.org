#+title: Changelog

* Unreleased
- Media commands act on the tab that plays.  Each command is one JXA call (JS =mediaRun=) that lists the media tabs, checks which play, and picks the target: the tab picked with ~navegosa-media-select-tab~, else a playing one (the last controlled first), else the last controlled, else the shown one.  Before, a cached window and tab index could point at another tab once tabs moved, so play/pause resumed a random video.
- Tabs are tracked by the browser's tab id (=showTabById=, =mediaFullscreenToggle= by id); =mediaCommand= and =mediaStatus= are gone.
- ~navegosa-media-play-pause~ never leaves two videos playing: it pauses every other playing tab first.  ~navegosa-media-open-url~ pauses playing tabs before it opens the new one and picks it.
- ~navegosa-media-select-tab~ marks playing tabs with ♫ (players on the MPRIS lane too), and the pick holds until ~navegosa-media-clear-pick~.
- Add ~navegosa-media-pause~; with a handler it hands over the paused tab's URL, time and rate, so playback can continue elsewhere.  The MPRIS lane gains =pause=.
- Add ~navegosa-media-play-url-at~, the way back: it plays a URL from a time at a rate in the media tab that shows the same video (YouTube matches by video id), or in a new tab opened at that time.  It retries while the tab loads, and other playing tabs pause.  The MPRIS lane opens the timestamped URL.
- An unloaded (Memory Saver) tab no longer stalls every command: the script names each tab before checking it, and a tab silent for ~navegosa-media-check-timeout~ is skipped for a minute while the command runs again.
- =make test= also runs =node --test test/= against a fake browser, and the batch Emacs runs in a sandboxed =--init-directory=.
- Media commands keep keyboard focus in Emacs: ~navegosa-media-select-tab~ and ~navegosa-media-open-tab~ show the tab in its window without activating the browser (JS =showTab=; =activateTab= still activates, for the general tab switchers).
- ~navegosa-media-fullscreen-toggle~ toggles the player's own fullscreen instead of macOS window fullscreen: a key posted to the browser process (=CGEventPostToPid=, F19) gives the page the user gesture the Fullscreen API demands without activating the browser, then YouTube's fullscreen button (else the video element) takes over.  Exiting calls =document.exitFullscreen()=, which needs no gesture.
- Entering fullscreen still activates the browser, twice: ~navegosa--reclaim-focus~ starts a JXA watcher that re-activates Emacs every time the browser comes to the front, for ~navegosa-reclaim-focus-wait~ seconds.

* 0.5.0 (2026-08-05)
- Linux gap lanes: what MPRIS cannot carry now rides the audio server and the compositor; only what no lane can honor still signals the honest ~user-error~.
- Volume/mute via =pactl= on the browser's sink-inputs (matched from the MPRIS bus name); clamped at 100%, browser-wide, honest error when no audio flows. Server-side mute keeps the media session registered - tab mute would deregister it.
- Add =navegosa-keysend.el= - deliver the page's own shortcut keys to the browser window through the compositor: ~navegosa-keysend-function~ backend hook (nil disables) with a Hyprland default (~navegosa-keysend-hyprland~; batched focus bounce, since Chromium ignores synthetic keys while unfocused), ~navegosa-keysend-keys~ action-to-key alist (YouTube defaults).
- Subtitles (=c=), theater (=t=), and speed (=<= / =>=, routed by direction, page-quantized) work on the MPRIS lane through keysend; speed reset stays impossible (no page key).

* 0.4.0 (2026-08-05)
- Add =navegosa-mpris.el= - Linux transport for the same ~navegosa-media-*~ commands over the browser's MPRIS D-Bus interface (built-in =dbus.el=, in-process, ~1ms per call); transport picked per-OS in ~navegosa-media--dispatch~.
- Player discovery filters bus names by playback status (browser names linger after media ends) and ranks per ~navegosa-mpris-player-priority~, browsers first; cache with revalidation and retry-once on D-Bus errors.
- All seeking via =SetPosition= - relative =Seek= is quantized by the page's own MediaSession handlers; echo predicts the seek target and the flipped pause state.
- Honest degradation where browsers ignore the protocol: speed, volume, mute, subtitles, theater, fullscreen signal a ~user-error~ with the reason; ~navegosa-media-copy-url~ requires =xesam:url= (Firefox yes, Chromium no); next/prev guarded by =CanGoNext=/=CanGoPrevious=.
- ~navegosa-media-open-url~ on Linux falls back to ~browse-url~ and re-attaches control to whatever starts playing.

* 0.3.0 (2026-08-05)
- Add =navegosa-media.el= - media playback control in browser tabs: play/pause, seek, speed, volume, mute, subtitles, next/prev, theater mode, window fullscreen, timestamped URL copy, status echo.
- Tab discovery by URL prefilter (~navegosa-media-url-patterns~) with cache and retry-once; every JXA call deadline-guarded (~navegosa-media-timeout~) against discarded-tab hangs.
- ~navegosa-media-open-url~ opens a URL as the browser's front tab (no focus steal) and controls it; ~navegosa-media-select-tab~ always prompts and shows the picked tab.
- Extract ~navegosa--build-script~ / ~navegosa--parse-result~ shared runner helpers.
